# OpenMontage 异步分镜生成与资源生成计划

日期：2026-07-21  
状态：需求已确认，待实施

## 1. 目标

让没有视频制作经验的用户完成一条清晰的生产路径：

`灵感对话 -> 创建分镜 -> 可选控制成片首尾 -> 一键生成镜头 -> 合成视频`

生成过程必须是后台任务。用户提交后可以继续编辑、切换镜头、查看资源库或离开当前页面，不得被单个供应商请求锁住整个工作台。

## 2. 已确认的业务规则

### 2.1 灵感创建阶段

灵感对话确认后，一次性创建完整的分镜数据，包括：

- 镜头顺序、镜头描述、提示词、镜头语言和时长；
- 角色、场景、道具等计划资源及其绑定关系；
- 每个镜头的连续性模式和首尾帧字段；
- 当前短视频或当前集的可选成片首尾控制配置。

用户可以选择“控制成片首尾画面”：

- 开启时：第一个镜头的首帧和最后一个镜头的尾帧由 GPT 生图；
- 单镜头视频：允许同时生成首帧和尾帧；
- 关闭时：不调用 GPT 生图，不产生额外图片任务；
- 首尾控制帧任务在分镜创建后异步执行，完成后将资源 ID 回填到对应镜头。

小白用户默认不需要理解模型、资源 ID 或首尾帧字段；首尾控制属于可选的高级创作能力。

### 2.2 中间镜头连续性

中间镜头不使用 GPT 生图作为衔接帧。沿用当前代码已经实现的本地帧提取机制：

1. 上一个镜头视频完成；
2. 从视频尾部解码并提取最后一个有效画面；
3. 将画面注册为 `video_frame` 资源，成本为 0；
4. 下一个镜头通过 `inherit_previous_tail` 继承该资源作为首帧。

默认规则：

- 第一个镜头：首帧不强制，视频完成后提取尾帧供下一镜使用；
- 中间镜头：默认继承上一镜尾帧，并在生成后提取本镜尾帧；
- 最后一个镜头：默认继承上一镜尾帧，尾帧不强制；
- 单镜头视频：首帧和尾帧均可选；
- 用户显式选择或上传的首帧优先于继承帧；
- 明确设置为硬切或关闭连续性的边界不启用继承。

### 2.3 依赖失败

如果当前镜头需要上一镜尾帧，但上一镜没有完成视频且没有可用首帧，则不自动扩大用户选择范围、不退化为纯文本生成，提示：

`上一个分镜未生成，暂时无法生成当前分镜。`

如果上一镜也在本批次中，当前镜头进入等待；上一镜成功并完成尾帧提取后才继续。上一镜失败时，依赖镜头标记为未执行并显示依赖失败原因。

## 3. 批量选择范围

### 3.1 分镜页

- 作用域限定为当前短视频或当前集；
- 支持全选、取消全选和部分选择；
- 一键提交后，每个镜头成为一个子任务；
- 非连续选择不自动补选未选择的上一镜；缺少依赖时按 2.3 阻止该镜头。

### 3.2 资源库

- 支持资源单选、多选、全选和取消全选；
- 角色、场景、道具图片生成作为独立子任务；
- 资源之间没有连续帧依赖，可以在受限并发下执行；
- 生成完成后自动写入资源库，并同步当前项目的计划资源。

## 4. 异步任务架构

### 4.1 任务层级

使用一个批次父任务和多个子任务：

- 父任务：记录本次分镜批量生成或资源批量生成；
- 子任务：单个 GPT 首尾帧、单个资源图片或单个镜头视频；
- 子任务保存提交时的项目版本、镜头版本、提示词、模型、引用资源和依赖关系，避免用户后续编辑覆盖正在执行的输入。

任务状态至少包括：

`queued -> running -> complete`

以及：

`awaiting_payment`、`waiting_dependency`、`failed`、`cancelled`、`partial_failure`。

计费任务必须保留现有报价、支付、重试、结算和结果可见性语义，不能因为异步化而提前扣费或丢失恢复信息。

### 4.2 调度策略

- 资源图片和独立首尾控制帧：队列内受限并发；
- 同一集镜头：按镜头顺序排队，因为下一镜依赖上一镜刚提取的尾帧；
- 不同项目或无依赖任务：允许有限并发；
- 不使用无限并发，也不把阻塞的供应商调用直接放回 FastAPI 请求协程；
- worker 失败、进程重启或前端离开后，任务可以依据持久化状态恢复或重试。

### 4.3 后端接口方向

新增统一任务接口，具体路径在实施时按现有路由风格确定：

- 提交分镜批量生成，立即返回 `202` 和父任务 ID；
- 提交资源批量生成，立即返回 `202` 和父任务 ID；
- 查询项目任务列表和单个任务详情；
- 重试失败子任务；
- 通过现有项目 SSE 推送任务状态和子任务进度。

现有 `/images/generate`、`/shots/{shot_id}/regenerate` 的同步供应商调用需要改为入队执行；现有尾帧解码、资源持久化和分镜更新逻辑继续复用。

SSE 只负责实时通知，任务状态必须可从服务端持久化记录恢复，不能只依赖进程内存中的 `EventBus` 历史。

## 5. 前端交互

### 5.1 灵感与创建

- 灵感确认界面提供可选的“控制成片首尾画面”；
- 默认关闭，开启后展示首帧/尾帧生成状态；
- 计划创建完成后直接展示完整分镜，不要求用户手工填写首尾帧 ID；
- 首尾帧仍在生成时显示准备中，不重复提交同一任务。

### 5.2 分镜页

- 镜头列表增加复选框、全选和取消全选；
- 增加“一键生成镜头”主按钮；
- 每个镜头显示排队、等待上一镜、生成中、已完成、失败和依赖失败；
- 正在生成的镜头只锁定自身重复操作；
- 不再用 `operationPending` 或 `anyCommandPending` 锁住整个工作台；
- SSE 断线或重新进入项目时，重新查询任务并恢复状态。

### 5.3 资源库

- 资源卡增加选择状态、全选和批量生成入口；
- 单个资源仍可从卡片直接生成；
- 资源生成中只锁定对应资源；
- 任务完成后自动刷新媒体预览、资源状态和项目资源绑定。

### 5.4 合成入口

- 只有当前选择范围所需的镜头都完成，或用户明确选择已有成片复用时，才允许合成；
- 缺失依赖、失败镜头和未完成首尾控制帧必须在合成入口明确显示；
- 合成任务同样采用异步提交和状态恢复。

## 6. 数据一致性与安全

- 任务执行前锁定镜头版本和计划资源版本；
- 用户在任务期间修改镜头时，旧任务结果不得覆盖新版本；
- 镜头视频发布后统一调用现有尾帧提取和连续性更新逻辑；
- 资源生成结果必须写入数据库资源表和兼容的项目 artifact；
- 项目、用户和计费任务必须在每次查询、重试和媒体访问时校验归属；
- 重复点击使用幂等键，不能产生重复供应商请求或重复扣费。

## 7. 实施阶段

### Phase 1：任务基础设施

- 确定任务持久化模型、父子关系、状态转换和幂等键；
- 建立受限 worker/队列；
- 增加任务查询、重试和 SSE 事件；
- 覆盖重启、重复提交和失败恢复测试。

### Phase 2：资源图片异步化

- 将资源图片生成改为入队返回；
- 支持资源库单选、多选和全选；
- 保留报价、支付、重试和资源回填语义；
- 将镜头首帧/尾帧 GPT 生成复用同一图片任务能力。

### Phase 3：灵感首尾控制

- 在灵感创建阶段记录可选的成片首帧/尾帧意图；
- 开启时自动创建 GPT 图片子任务；
- 任务完成后将生成资源 ID 填入首个/最后一个镜头；
- 关闭时不创建图片任务。

### Phase 4：分镜异步生成

- 支持当前集镜头全选和部分选择；
- 按集内顺序执行视频任务；
- 每个镜头完成后执行尾帧提取并解锁下一镜；
- 缺少上一镜成片时返回明确依赖提示；
- 保留现有首帧显式选择和连续性覆盖规则。

### Phase 5：小白工作流与合成

- 串联灵感、分镜生成和合成的主按钮与状态展示；
- 移除生成期间的全局交互锁；
- 增加断线重连、刷新恢复和批次部分失败处理；
- 进行真实浏览器端到端验收。

## 8. 验收标准

- 不设置成片首尾控制时，灵感创建不会触发 GPT 首尾帧生成；
- 设置后，首帧只写入第一个镜头，尾帧只写入最后一个镜头；
- 中间镜头使用本地解码的 `video_frame` 尾帧继承，不产生 AI 图片费用；
- 选择一集全部镜头时，镜头按依赖顺序自动完成；
- 只选择中间镜头且上一镜未完成时，显示指定依赖提示，不自动补选；
- 资源库可单选、多选、全选并异步完成；
- 提交接口不等待供应商响应，前端可以继续操作其他镜头和资源；
- 刷新页面或 SSE 断线后，任务状态和已完成媒体能够恢复；
- 任何失败、支付等待或依赖阻塞都不会静默生成错误视频或重复扣费；
- 镜头全部完成后可以一键进入异步合成并得到最终视频。

## 9. 明确不做

- 不为中间镜头额外调用 GPT 生图制作衔接帧；
- 不自动把用户未选择的上一镜加入批次；
- 不在供应商请求期间阻塞 HTTP 请求或锁定整个前端；
- 不用纯文本视频生成静默替代缺少首帧依赖的镜头；
- 不改变现有供应商能力声明、计费结果可见性和媒体访问授权规则。
